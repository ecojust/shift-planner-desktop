# 排班 plus · 通用员工排班

独立的 Vue / TypeScript / Vite 排班应用，适合早晚班、请假安排和公平轮班。同一套界面支持静态网页和 Tauri 桌面版：桌面版内置 Python OR-Tools CP-SAT 求解器，在本机计算，不需要业务服务器，也不依赖其他游戏项目或 GameLink SDK。

## 网页启动与构建

在本项目 `shift-planner` 根目录运行（Node.js 版本见 `package.json`）：

```sh
npm ci
npm run dev
# 打开终端显示的本地地址
npm run build
npm test
```

构建产物位于 `dist/`，可部署到静态网页服务器。请通过 HTTP 服务访问，不要直接双击构建目录的 HTML。

## Windows / macOS 桌面版

开发构建需安装 Node.js、Python 3.12、Rust stable 及目标系统的原生构建工具，完整准备说明见 [桌面构建指南](docs/DESKTOP_BUILD.md)。在对应系统上运行：

```sh
npm ci
npm run desktop:dev
# 生成目标系统的安装包
npm run desktop:build
```

`desktop:dev` 启动前只检查并按需准备项目内的 `solver/.venv`，运行 `--info` 和小型求解自检，然后直接使用该环境中的 Python 执行求解源码，**开发启动不再冻结或运行单文件求解器**。已有同架构、依赖完整的环境会复用，更新源码不需要每次重新下载整套依赖。

`desktop:build` 才会检查并按需生成 PyInstaller `onedir` 运行目录，把 Python、OR-Tools 和关联库作为 Tauri 资源完整打进安装包。`desktop:prepare` 可手动准备发行运行目录，不是开发启动的必要步骤。最终使用者无需安装 Python。Windows 和 macOS 分别原生构建；macOS Intel 与 Apple Silicon 分别生成对应架构的包。

桌面版通过 Tauri 调用随包分发的本地求解进程，网页仍使用浏览器 Worker 中的启发式排班。桌面引擎不可用时会显示错误，不会悄悄换成网页算法。求解支持取消，未完成或失败时保留原表；桌面 Excel、CSV 和 JSON 导出使用系统文件保存对话框。

Windows x64、Intel Mac 和 M 芯片 Mac 已完成原生构建及最终资源目录内的求解验证：[下载安装包和源码](https://github.com/ecojust/shift-planner-desktop/releases)。已发布版本的三个平台曾完成 12 人整月排班：155 个班位、零缺员、独立规则检查零问题。新增月最低工时后，旧示例的每日 5 个班位不足以满足全部成员的全职最低；新规则和安装包的验证范围应分别查看记录。Windows 已验证 NSIS 静默安装；桌面图形界面交互、Mac 人工安装/卸载及文件对话框尚未实测，完整范围见 [验证记录](docs/VERIFICATION.md)。Mac 要求 macOS 14+，未进行 Apple Developer ID 签名或公证。

在 GitHub Actions 手动运行 **Build desktop installers**，会并行构建 Windows x64、Intel Mac 和 M 芯片 Mac；三个平台全部测试和包内求解验证通过后，自动发布包含三个安装包、对应源码和 SHA256SUMS 的 GitHub prerelease。JSON 验证报告留在 Actions Artifacts 中，保留 14 天。只需要 M 芯片时，也可运行 **Build macOS Apple Silicon installer**。各平台最新验证范围见下方构建说明。

若遇到引擎启动问题，可运行 `npm run solver:doctor`，报告保存到 `solver/build/diagnostics-latest.json`。它对比项目 Python 与已打包运行目录的加载及小型求解，不读写员工数据，也不联网。升级时请同步覆盖 `scripts/`、`src-tauri/` 的源码与配置、`src/`、`solver/` 源码以及项目清单，保留正确架构的 `solver/.venv` 和应用本地数据；详见 [更新与诊断](docs/DESKTOP_BUILD.md)。

1.1.1 补齐 Mac App 和内置 Python 框架的签名资源封印，修复旧包严格验签失败。仍未进行 Apple 公证，首次启动可能需要在“系统设置 → 隐私与安全性”对本应用选择“仍要打开”。细节见 [Mac 打包说明](docs/DESKTOP_BUILD.md#mac-提示应用已损坏)。

## 功能与数据

- 管理员工、岗位、分组、可上班次、月最低工时、周最低/最高工时及请假日期。
- 月参考工时默认按所选月份工作日 × 8 计算，包含节假日、调休补班与手动日历；支持按月覆盖，个人月最低默认跟随，也可自定义。
- 自定义班次名称、时段、颜色、每日所需人数及每人每班的固定津贴，支持跨午夜的晚班。
- 设置最短休息间隔、连续工作天数和团队每周上班权重；选择星期并设置合计百分比，硬性配额不满足时保留原表。
- 设置员工互斥组，避免组内员工同一天排同一个班次；可限定班次，未选择班次表示应用于全部班次。
- 生成日历排班，并允许手动调整、锁定班次与锁定休息。
- 显示人员覆盖缺口及冲突提示，提供员工工时统计。
- 导出真正的 `.xlsx` Excel 文件，包含排班表、班次说明与津贴明细；另支持 UTF-8 CSV。
- 按实际排班次数累计固定津贴，每天以金色金额显示，右侧汇总个人月总额；津贴不随工时、工资、倍率或节假日变化。
- 自动保存在当前浏览器，也可导入或导出 JSON 备份。

网页算法遵循配置的硬约束，人数不足时保留缺口，公平分配采用启发式方法，不保证数学上的全局最优解。桌面 CP-SAT 默认要求覆盖完整人数；只有明确开启“允许缺员”时才优化缺口，并在满足其他硬规则的前提下分配。公平性目标包括按工时上限归一的工作量差和各班次次数差；旧版周末均衡选项已移除。启用上班权重后，星期配额和周班次需求都必须完整满足，“允许缺员”不会放宽这些要求。

桌面求解明确区分最优方案、可行方案、已证明无解，以及超时尚未找到方案；超时不等于无解。结果还会通过前端独立规则检查，检查失败不会覆盖原表。锁定或手动安排仍可能形成冲突，请检查结果后确认发布。切换月份时保留其他月份已有排班，让已知的跨月休息、连续工作及自然周工时参与约束判断；没有录入的历史排班无法推断。

互斥组至少包含 2 名员工，规则针对同日同班，不会禁止他们在同一天分别上早班和晚班。手动安排休息时，可选择锁定；未锁定的休息在再次生成时允许重新分配，锁定休息会保留。

跨午夜班次以开始日期归属日历格子；排班表、Excel 和最低工时检查均按实际时段归属自然月，上月夜班进入本月的部分计入，月底跨出部分不计。固定津贴全部归属班次开始日期，跨夜、跨月均只计一次，不按小时拆分。周最低按周一至周日计算，不足完整周按当月所占天数 / 7 折算；周最高仍包含完整自然周内已知的跨月排班。请假不自动降低最低工时，可为个人设置自定义值。具体口径见[工时设置说明](docs/HOURS.md)。上班权重按团队班次数计算，不按人数去重或工时占比；边界周保留原星期份额，不重新归一，计算与示例见[上班权重说明](docs/WEEKDAY_WEIGHTS.md)。

日历使用固定版本 lunar-typescript 1.8.6 的离线数据，用于日期标签和月参考工时；日期类型不会改变班次津贴。当前完整识别 2025、2026 年，库未覆盖年度等无法确定的情形标记「待核对」，可手动确认工作日安排。新年度数据需升级依赖并重新构建，不会实时联网补齐。手动日历优先，并保留在 JSON 备份中。

例如夜班津贴设为 50 元，一位成员当月排 6 次夜班，就领取 300 元。休息不发放，跨夜不会重复领取；调整班次津贴后，当月排班表和 Excel / CSV 导出同步重新计算。没有单独的日期津贴设置，旧备份中的工资和倍率字段不参与计算。具体口径见[津贴计算说明](src/PAYROLL.md)。

## 本地保存与备份

数据保存在 `localStorage` 的 `shift-planner:v1` 项下，网页与桌面 WebView 各自保存在当前本地环境，不会自动同步。清除站点或应用数据、无痕窗口结束、切换设备或更换访问域名都可能导致无法继续读取原记录；请定期导出 JSON 备份，也可用备份在网页和桌面版之间迁移。

导入限制 2 MB、200 名员工、24 种班次，校验有效日期、时间、数值边界、重复排班及员工/班次引用。导入失败时应保留当前数据。Excel 文本采用明确的字符串类型；CSV 对可能触发公式的文本增加保护。CSV/Excel 用于查看或交付，恢复编辑请使用 JSON 备份。

## 需求来源

用户提供的微信文章及视频在当前环境返回 403，未能读取。本应用根据用户确认的「通用员工排班：早晚班、休假、公平轮班」及后续补充的自定义规则、Excel 导出、固定班次津贴需求实现，不声称复刻文章或视频内容。

另核对了 PerfectTablePlan 的官方遗传算法介绍，可参考其锁定、软偏好与限时优化的产品思路，详见 [PerfectTablePlan 参考记录](docs/PERFECTTABLEPLAN_REFERENCE.md)。本项目的桌面求解核心仍为 OR-Tools CP-SAT，没有改用遗传算法，也不声称复用了该软件的实现。

本次桌面构建、真实求解及界面验证范围详见 [验证记录](docs/VERIFICATION.md)。

右上角构建号采用北京时间 `YYYY.MMDD.HHmm`，在开发服务启动或编译时固定。同次 CI 的三个平台及失败重跑使用同一个构建号。可设置 `SHIFT_FLOW_BUILD_VERSION` 复现指定编号，格式或日期不合法会拒绝构建。安装包版本与构建号分别记录。
