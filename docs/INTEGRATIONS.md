# MCP 与 HTTP API

桌面版内置 MCP 与 HTTP API 服务。外部 AI 可读取当前应用的数据，修改人员、班次、规则和排班，调用内置求解器按配置生成排班，并检查规则冲突。

## 开启与连接

1. 点击桌面应用右上角最右侧的**齿轮（设置）**，按需开启 **MCP** 或 **HTTP**，也可同时开启。
2. 每项服务分别显示运行状态、连接地址和访问令牌。
3. 使用 MCP 时，复制包含实际地址和 MCP 令牌的配置到支持 Streamable HTTP 的 AI 客户端；使用 HTTP API 时，复制 HTTP 地址和 HTTP 令牌，按下方接口说明调用。

两项服务均内置于桌面应用，无需安装 Node.js、下载项目源码或运行命令。MCP 与 HTTP API 独立启停，使用各自的端口和访问令牌；开启或关闭其中一项不会影响另一项。

两项服务仅监听本机 `127.0.0.1`：MCP 默认端口为 `4318`，HTTP API 默认端口为 `4319`。各自端口被占用时会自动选择可用端口，请以设置显示的实际地址为准。每次开启都会生成该服务的新访问令牌，重新开启后需更新对应客户端配置；另一项正在运行的服务仍保留自己的地址和令牌。

关闭设置弹窗后，已开启的服务继续运行。关闭某一开关只停止对应服务，退出应用会停止两项服务；重新打开应用时两项默认关闭，按需开启。网页版无法运行这些本地服务，需要使用桌面版。

## 修改权限

在设置中选择允许外部 AI 修改的数据类别。MCP 与 HTTP API 共用这些权限，每次写入都会检查当前设置；更改权限立即生效，无需重启服务。读取数据和检查排班冲突不受写入权限影响。

| 权限 | 默认值 | 对应数据 |
| --- | --- | --- |
| 成员 | 开启 | `employees` |
| 班次 | 关闭 | `shifts` |
| 排班规则 | 关闭 | `rules`、日期设置 `calendar` |
| 排班结果 | 关闭 | `assignments`，包括新增、修改、删除排班及锁定状态 |

默认仅允许修改成员。需要让 AI 安排班次时，先开启「排班结果」权限；求解器生成、`set_assignment`、`POST /api/assignments` 和完整文档中的排班变更都受此权限控制。

整体替换文档也会比较实际变更的字段，不能通过 `replace_state` 或 `PUT /api/state` 绕过权限。一次请求包含任何未授权修改时，整个请求都会被拒绝，数据不会部分更新：HTTP 返回 403，MCP 返回 `isError: true`。删除成员时，如果同时需要清理该成员的排班或规则，还需开启相应类别的权限。

团队名称 `teamName`、当前月份 `month` 和津贴配置 `payroll` 不开放外部修改。提交完整文档时应保留这些字段及其他未获授权字段的原值。

## 修改来源

成员、班次、排班规则等每张配置卡最多显示一个最近修改状态：手动修改（`manual`）、MCP（`mcp`）或 HTTP（`http`）。卡片没有保存记录且没有草稿变化时，不显示状态。

MCP／HTTP 修改使用高对比底色、图标和「MCP 修改」「HTTP 修改」文字，方便一眼识别外部修改；手动修改保持轻量样式。

卡片内尚未保存的修改合并显示为一个「未保存」状态。悬停、键盘聚焦或点击状态，可查看最近一次已保存的修改来源及 `YYYY-MM-DD HH:mm:ss` 格式的具体时间（本机时间）；有草稿变化时仍可查看上一次保存记录。

恢复默认日期类型、清除头像或关闭上班权重时，也会保留最后修改来源。完整 JSON 备份和恢复会保留来源记录；写入权限单独保存在本机，不随备份导入改变。

外部 AI 修改配置后，应用会保留配置变更提示，显示来源、时间和受影响的配置类别，方便用户检查。来源记录和提示随排班数据保存，重启应用后仍保留。提示持续显示到用户点击「已核对变更」；重新生成排班不会自动清除，因为全局配置也会影响其他月份。

读取接口中的 `state.provenance` 仍保留字段级来源和时间记录，供兼容和完整备份使用；界面按配置卡汇总显示。这些记录由应用根据实际修改自动生成。外部调用传入的 provenance 不会被采纳，不能用它伪造修改来源、时间或清除配置变更提示。

## 每月排班状态

点击顶部日历，在每个月份选项内查看排班状态，也可切换年份；排班日历标题区域不再重复显示。该月没有排班记录、也没有成员已完成生成的记录时为「未排班」；存在记录（包括 `off` 休息）或已生成的全休月份均视为已有排班。未失效的月份会按规则检查区分「已排班」「已排班 · 跨月待确认」及「排班有冲突，需重新检查」；悬停可读完整原因。

保存成员、班次或排班规则的变更后，所有已有排班的月份都会显示「规则已修改，排班已失效」，原排班仍保留。规则导入如果改变这些配置，也会使已有排班失效。

自动排班成功并保存后，仅解除生成目标月份的失效状态；通过 MCP／HTTP 调用求解器生成也遵循此规则。生成失败、未保存的草稿修改，以及点击「已核对变更」均不会解除失效。MCP／HTTP 的单条排班修改也不会解除；通过 `replace_state` 或 `PUT /api/state` 提交完整文档时，只有本次未修改配置、排班实际变化且检查无规则错误并满足覆盖要求的月份，才解除配置失效；跨月信息不完整时仍显示待确认。

状态随数据保存，重启后保留；完整备份恢复其自身状态。旧数据已有排班记录但没有失效历史时，会按当前规则及跨月已知情况显示已排班、跨月待确认或实际冲突，不推断缺失的历史排班。

## 排班生成与更新时间

开启「排班结果」权限后，MCP 或 HTTP 成功写入排班结果，排班日历主页会显示当前月份最近一次外部排班生成／更新时间及来源，精确到秒。此时间是软件成功保存结果的时间，由软件记录，不能由调用方指定。

记录按目标月份分别保存；更新其他月份不会改变当前月份的时间。调用求解器成功生成并保存时，即使结果与原排班相同，也会更新生成时间并解除该月失效状态。普通写入接口提交相同排班、仅修改配置、读取数据、请求被拒绝或保存失败时，不更新排班时间。后续手动调整仍保留最近一次外部写入时间。时间保存在 `state.provenance.scheduleUpdates`，重启和完整备份恢复后保留；没有历史记录的月份不会补造时间。

## 数据与冲突

接口直接操作应用当前的排班文档，与界面共享同一份数据。外部写入通过校验并保存成功后才更新界面；整体替换文档使用与备份恢复相同的格式校验。

所有写入必须提供最近一次读取返回的 `revision`。文档变化后 revision 会更新，旧版本写入会被拒绝：HTTP 返回 409，MCP 返回 `isError: true`。重新读取最新数据后再提交修改。

应用正在编辑数据或生成排班时，外部写入也会暂时被拒绝（HTTP 409 / MCP 工具错误），避免覆盖尚未完成的操作。完成编辑或生成并返回排班日历后，重新读取数据并重试。

## HTTP

先在设置中开启 **HTTP**。每个请求均需要 `Authorization: Bearer <HTTP 访问令牌>`，写入请求体为 JSON。HTTP 服务只提供下列五种接口，不提供 `/mcp`；MCP 服务地址也不提供这些 HTTP 接口。以下示例使用 HTTP 默认端口 `4319`，请按设置中的实际地址调整。

```bash
curl http://127.0.0.1:4319/api/state \
  -H 'Authorization: Bearer <HTTP 访问令牌>'
```

| 方法与路径 | 请求体 / 返回 |
| --- | --- |
| `GET /api/state` | 返回当前文档 `{ revision, state }` |
| `PUT /api/state` | 请求 `{ revision, state }`，按修改权限校验并整体替换文档，返回 `{ revision, state }` |
| `POST /api/assignments` | 更新一个人一天的排班，参数见下表，返回 `{ revision, state }` |
| `POST /api/schedules/generate` | 按当前保存配置调用内置求解器，参数及结果见下文 |
| `GET /api/validate` | 返回 `{ revision, issues }`，检查当前排班的规则冲突 |

`PUT /api/state` 接收当前文档的完整替换内容，不是局部字段补丁。先用 `GET /api/state` 获取最新的 `{ revision, state }`，在完整 `state` 中修改获授权的数据，再将两者一起提交。必须保留其他字段和所有月份的排班；只提交成员列表等部分内容会被拒绝，省略可选配置也可能被视为删除。成员、班次和规则的批量修改都使用此接口，没有独立的成员／班次／规则写入路由。

例如将读取结果保存为 `state.json`，编辑其中目标成员的 `name`，保留其余文档和此次读取的 `revision` 后提交：

```bash
curl http://127.0.0.1:4319/api/state \
  -H 'Authorization: Bearer <HTTP 访问令牌>' \
  -o state.json

# 编辑 state.json 后提交完整的 { revision, state }
curl -X PUT http://127.0.0.1:4319/api/state \
  -H 'Authorization: Bearer <HTTP 访问令牌>' \
  -H 'Content-Type: application/json' \
  --data-binary @state.json
```

`POST /api/assignments` 参数：

| 参数 | 要求与含义 |
| --- | --- |
| `revision` | 必填，最近读取返回的版本 |
| `employeeId` | 必填，已有成员 ID |
| `date` | 必填，`YYYY-MM-DD` 日期 |
| `shiftId` | 新增／修改时必填，已有班次 ID；`"off"` 表示休息 |
| `locked` | 可选布尔值，设置该条排班是否锁定；默认 `false` |
| `remove` | 可选布尔值，`true` 表示删除该条排班，删除时无需 `shiftId` |
| `unlock` | 可选布尔值，修改或删除已锁定排班时必须显式设为 `true` |

例如先开启「排班结果」权限并读取 revision，再提交一条排班：

```json
{
  "revision": "<最近读取到的 revision>",
  "employeeId": "employee-1",
  "date": "2026-10-15",
  "shiftId": "<已有班次 ID>",
  "locked": false
}
```

删除已锁定排班时，提交 `{ "revision": "<当前版本>", "employeeId": "employee-1", "date": "2026-10-15", "remove": true, "unlock": true }`。完整文档替换可按授权批量更新排班及锁定状态。

完整文档结构与应用导出的 JSON 备份一致。无效日期、未知员工或班次、重复排班等会被拒绝；规则冲突可通过 `GET /api/validate` 检查，手动排班仍允许保留待解决的规则冲突。

### 按配置生成排班

`POST /api/schedules/generate` 与 MCP 的 `generate_schedule` 调用桌面版内置 OR-Tools CP-SAT 求解器，读取软件已经保存的成员、班次和规则，保留本月锁定排班，并在月初和月末扩展到完整自然周，计入上月、下月已有记录。请求不接受调用方提供的 `state`、随机种子或局部排班选项。

| 参数 | 要求与含义 |
| --- | --- |
| `revision` | 必填，最近一次读取返回的版本 |
| `month` | 可选，`YYYY-MM`，年份 1900–2200；省略时使用请求开始时软件当前激活的月份 |
| `timeLimitSeconds` | 可选，1–60 秒，默认 15 秒；求解器计算时限 |

先开启「排班结果」权限并读取 revision，再提交：

```bash
curl -X POST http://127.0.0.1:4319/api/schedules/generate \
  -H 'Authorization: Bearer <HTTP 访问令牌>' \
  -H 'Content-Type: application/json' \
  --data '{"revision":"<最近读取到的 revision>","timeLimitSeconds":15}'
```

指定月份时，在请求体中增加 `"month":"2026-11"`。这不会切换软件当前激活的月份。设置弹窗提供可复制的 JavaScript 示例，会先读取最新 revision 再生成。

成功返回 `{ success: true, saved: true, month, status, message, issues, stats, revision, state, generatedAt }`。结果经过独立规则检查并保存后才返回成功；只替换目标月份的排班，保留锁定记录、其他月份和原配置。

跨月计算按成员、日期区分已知安排与未知空白。相邻月已有工作／休息记录固定保留，即使未锁定或已失效也不会自动覆盖。过去缺失记录不视为休息，不为其虚构班次；对应周返回历史待核对警告。未知的今天与未来日期会临时试排，验证自然周能否衔接；成功保存只记录目标月已完整生成，不把相邻月标为已排班。

生成响应还可包含：

- `boundaryPreview: Assignment[]`：临时安排在月外未来日期的工作班次，空白在本次预排中表示休息。该数组不写入 `state.assignments`，也不属于已保存的相邻月排班；调用方不可把它当作相邻整月已完成的保证。
- `boundaryContext: { startDate, endDate, referenceDate, incompleteHistory }`：本次完整自然周计算范围、冻结的本机参考日期，以及未知过去记录。`incompleteHistory` 每项为 `{ employeeId, weekStart, unknownDates }`。参考日期由软件在请求开始时冻结，生成接口不接受外部指定。

`success: true` 表示目标月方案通过可核对范围的独立检查并已保存，不表示缺失历史已补齐，或尚未保存的未来预排已成为正式排班。调用方应同时读取 `issues` 与 `boundaryContext`，向用户保留待核对提示。之后生成相邻月份时，已保存的本月安排成为固定上下文；冲突时原表保留，不自动联排覆盖其他月份。


无解、求解器限时内没有找到结果，或结果未通过独立检查时，返回 `{ success: false, saved: false, month, status, message, issues, stats, revision }`，不修改数据。此类求解结果的 HTTP 状态仍为 200，调用方必须检查 `success`；MCP 工具同样返回结构化结果。参数错误、权限不足、数据版本冲突、服务关闭和请求超时分别使用 HTTP 400／403／409／503／504，MCP 返回错误响应。

求解器启动和结果检查需要额外时间，客户端请求超时建议至少设为 `timeLimitSeconds + 155` 秒。生成期间，应用会显示目标月份、调用来源和进度，并可取消；UI、MCP、HTTP 共用一个生成任务，重复生成及其他外部写入返回 409，读取和检查仍可用。提交前会再次检查配置版本、权限和服务状态；请求取消或服务关闭发生在提交确认之前时，不保存结果。已经接受提交的请求可能在客户端断开后完成保存，客户端应重新读取状态确认，避免自动重试覆盖结果。

## MCP

先在设置中开启 **MCP**。MCP 服务仅提供无会话的 Streamable HTTP 端点 `/mcp`，通过 POST JSON-RPC 返回 JSON，不提供 SSE 订阅或 `/api/*` 接口。客户端需支持自定义 Bearer 头，并使用 MCP 自己的访问令牌。可直接复制设置中的配置；以下为默认端口下的结构示例，具体字段依客户端而定：

```json
{
  "mcpServers": {
    "shift-schedule-expert": {
      "type": "http",
      "url": "http://127.0.0.1:4318/mcp",
      "headers": { "Authorization": "Bearer <MCP 访问令牌>" }
    }
  }
}
```

| 工具 | 参数 | 功能 |
| --- | --- | --- |
| `get_state` | `{}` | 获取完整文档和 revision |
| `replace_state` | `{ revision, state }` | 按修改权限校验、保存并替换完整数据 |
| `set_assignment` | 同 HTTP 单条排班请求 | 新增、修改或删除单条排班 |
| `generate_schedule` | `{ revision, month?, timeLimitSeconds? }` | 按保存配置调用求解器生成并保存目标月排班；默认当前激活月份 |
| `validate_schedule` | `{}` | 检查当前排班冲突 |

`replace_state` 与 `PUT /api/state` 使用相同的完整文档替换规则；`set_assignment` 使用上方单条排班参数。两项服务共享同一份当前排班文档、revision 和写入权限，成功写入后另一项服务读取即可获得更新。

成员工时仅使用 `minHoursPerWeek` 和 `maxHoursPerWeek`。旧文档中的 `minHoursPerMonth`、`monthlyReferenceHours` 会忽略并移除，单独改变这些已弃用字段不会保存新配置或使已有排班失效。读取接口、规则校验及自动生成均使用相同的周工时规则。

日期类型用于日历标记。修改日期类型仍记录来源和时间，但不会使排班失效；已有的失效标记仍需重新生成排班后清除。

完整文档中的 `scheduleCoverage["YYYY-MM"].employeeIds` 表示已完成该月生成的成员，由成功生成自动维护。该月的空白表示排班生成的休息，不会写入主动请假字段 `unavailableDates`。主动请假独立指定不可排日期。缺少该字段的旧文档仅有明确格子算已知，不能因为一条排班记录就认定整月完整；未生成日期仍属待排或未知历史。清空某月排班时软件会撤销对应完整性，删除成员会清理其生成范围。

`replace_state` / `PUT /api/state` 可以原样带回 `scheduleCoverage`，也可以省略该字段并保留软件当前生成范围；直接新增或修改生成范围会被拒绝（403）。外部新增单条排班不能把其他空白自动视为已生成的休息。完整性与规则有效性是两件事，仍须查看规则检查和跨月待确认提示。
