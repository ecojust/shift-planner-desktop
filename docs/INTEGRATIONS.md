# MCP 与 HTTP API

桌面版内置 MCP 与 HTTP API 服务。外部 AI 可读取当前应用的数据，修改人员、班次、规则和排班，并检查规则冲突。

## 开启与连接

1. 点击桌面应用右上角最右侧的**齿轮（设置）**，开启 **MCP**。
2. 设置会显示运行状态、MCP 地址、HTTP API 地址和访问令牌。
3. 复制 MCP 配置到支持 Streamable HTTP 的 AI 客户端，即可连接。复制的配置已包含实际地址和访问令牌。

无需安装 Node.js、下载项目源码或运行命令。HTTP API 与 MCP 共用内置服务和访问令牌，开启 MCP 后即可使用。

服务仅监听本机 `127.0.0.1`，优先使用端口 `4318`；端口被占用时自动选择可用端口，请以设置中显示的地址为准。每次开启都会生成新的访问令牌，重新开启后需更新 AI 客户端中的配置。

关闭设置弹窗后服务继续运行。关闭 MCP 开关或退出应用会停止服务；重新打开应用时默认关闭，按需开启。网页版无法运行此本地服务，需要使用桌面版。

## 修改权限

在设置中选择允许外部 AI 修改的数据类别。MCP 与 HTTP API 共用这些权限，每次写入都会检查当前设置；更改权限立即生效，无需重启服务。读取数据和检查排班冲突不受写入权限影响。

| 权限 | 默认值 | 对应数据 |
| --- | --- | --- |
| 成员 | 开启 | `employees` |
| 班次 | 关闭 | `shifts` |
| 排班规则 | 关闭 | `rules`、日期设置 `calendar`、月参考工时 `monthlyReferenceHours` |
| 排班结果 | 关闭 | `assignments`，包括新增、修改、删除排班及锁定状态 |

默认仅允许修改成员。需要让 AI 安排班次时，先开启「排班结果」权限；`set_assignment`、`POST /api/assignments` 和完整文档中的排班变更都受此权限控制。

整体替换文档也会比较实际变更的字段，不能通过 `replace_state` 或 `PUT /api/state` 绕过权限。一次请求包含任何未授权修改时，整个请求都会被拒绝，数据不会部分更新：HTTP 返回 403，MCP 返回 `isError: true`。删除成员时，如果同时需要清理该成员的排班或规则，还需开启相应类别的权限。

团队名称 `teamName`、当前月份 `month` 和津贴配置 `payroll` 不开放外部修改。提交完整文档时应保留这些字段及其他未获授权字段的原值。

## 修改来源

成员、班次、排班规则等配置字段旁会显示最近一次已保存修改的来源标记：手动修改（`manual`）、MCP（`mcp`）或 HTTP（`http`）。悬停、键盘聚焦或点击标记，可查看来源及 `YYYY-MM-DD HH:mm:ss` 格式的具体修改时间（本机时间）。尚未保存的编辑显示「未保存」，已有保存记录的字段仍可查看上一次保存时间。已有数据若没有来源记录，会显示「未记录」，从下次修改保存后开始记录。

恢复自动参考工时、恢复默认日期类型、清除头像或关闭上班权重时，也会保留最后修改来源。完整 JSON 备份和恢复会保留来源记录；写入权限单独保存在本机，不随备份导入改变。

外部 AI 修改配置后，应用会保留配置变更提示，显示来源、时间和受影响的配置类别，方便用户检查。来源记录和提示随排班数据保存，重启应用后仍保留。提示持续显示到用户点击「已核对变更」；重新生成排班不会自动清除，因为全局配置也会影响其他月份。

读取接口中的 `state.provenance` 包含这些来源和时间记录，由应用根据实际修改自动生成。外部调用传入的 provenance 不会被采纳，不能用它伪造修改来源、时间或清除配置变更提示。

## 排班生成与更新时间

开启「排班结果」权限后，MCP 或 HTTP 成功写入排班结果，排班日历主页会显示当前月份最近一次外部排班生成／更新时间及来源，精确到秒。此时间是软件成功保存结果的时间，由软件记录，不能由调用方指定。

记录按实际受影响的月份分别保存；更新其他月份不会改变当前月份的时间。仅修改配置、读取数据、提交相同排班、请求被拒绝或保存失败时，不更新排班时间。后续手动调整仍保留最近一次外部写入时间。时间保存在 `state.provenance.scheduleUpdates`，重启和完整备份恢复后保留；没有历史记录的月份不会补造时间。

## 数据与冲突

接口直接操作应用当前的排班文档，与界面共享同一份数据。外部写入通过校验并保存成功后才更新界面；整体替换文档使用与备份恢复相同的格式校验。

所有写入必须提供最近一次读取返回的 `revision`。文档变化后 revision 会更新，旧版本写入会被拒绝：HTTP 返回 409，MCP 返回 `isError: true`。重新读取最新数据后再提交修改。

应用正在编辑数据或生成排班时，外部写入也会暂时被拒绝（HTTP 409 / MCP 工具错误），避免覆盖尚未完成的操作。完成编辑或生成并返回排班日历后，重新读取数据并重试。

## HTTP

每个请求均需要 `Authorization: Bearer <访问令牌>`，请求体为 JSON。以下示例使用默认端口；实际地址和令牌可从设置中复制。

```bash
curl http://127.0.0.1:4318/api/state \
  -H 'Authorization: Bearer <访问令牌>'
```

| 方法与路径 | 请求体 / 返回 |
| --- | --- |
| `GET /api/state` | 返回当前文档 `{ revision, state }` |
| `PUT /api/state` | 请求 `{ revision, state }`，按修改权限校验完整文档并返回新快照 |
| `POST /api/assignments` | 请求 `{ revision, employeeId, date, shiftId, locked? }`，更新一个人一天的排班 |
| `GET /api/validate` | 返回 `{ revision, issues }`，检查当前排班的规则冲突 |

单条排班使用 `shiftId: "off"` 表示休息；`remove: true` 删除该记录，删除时无需 shiftId。已锁定的单条排班必须显式提供 `unlock: true` 才可修改或删除。整体替换文档可批量更新获授权的数据，包括排班的锁定状态，但仍会检查每类数据的实际变更权限。

例如先读取 revision，然后修改一条排班：

```json
{
  "revision": "<最近读取到的 revision>",
  "employeeId": "employee-1",
  "date": "2026-10-15",
  "shiftId": "<已有班次 ID>",
  "locked": false
}
```

完整文档结构与应用导出的 JSON 备份一致。更新成员、班次或规则时先读取完整文档，仅修改需要的字段，再提交 PUT。无效日期、未知员工或班次、重复排班等会被拒绝；规则冲突可通过 validate 检查，手动排班仍允许保留待解决的规则冲突。

## MCP

服务提供无会话的 Streamable HTTP 端点 `/mcp`，通过 POST JSON-RPC 返回 JSON，不提供 SSE 订阅。客户端需支持自定义 Bearer 头。可直接复制设置中的配置；以下为结构示例，具体字段依客户端而定：

```json
{
  "mcpServers": {
    "shift-schedule-expert": {
      "type": "http",
      "url": "http://127.0.0.1:4318/mcp",
      "headers": { "Authorization": "Bearer <访问令牌>" }
    }
  }
}
```

| 工具 | 参数 | 功能 |
| --- | --- | --- |
| `get_state` | `{}` | 获取完整文档和 revision |
| `replace_state` | `{ revision, state }` | 按修改权限校验、保存并替换完整数据 |
| `set_assignment` | 同 HTTP 单条排班请求 | 新增、修改或删除单条排班 |
| `validate_schedule` | `{}` | 检查当前排班冲突 |
